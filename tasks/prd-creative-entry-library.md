# PRD：创作条目与画布工作台

## 1. 文档状态

- 状态：产品讨论稿
- 目标：从产品语义定义工作台组织方式，并给出可落地的数据与技术边界。
- 设计结论：不引入“项目”实体；用 Creative Entry（创作条目）统一表达工作台可管理对象。首期条目类型为文件夹与画布。
- 范围说明：本方案不以仓库现有前端 demo 作为产品依据。后端具体模块归属待画布服务边界确定。

## 2. 背景与问题

创作者需要管理越来越多的画布，并按作品、客户、系列、阶段等自己的方式整理内容。若系统强制用户先创建“项目”，再把画布放在项目中，会额外引入固定业务层级；若文件夹只是画布集合，又无法统一表达目录中的文件夹、画布及顺序。

本方案将“文件夹”作为用户可定义的组织容器，将“画布”作为可编辑内容；二者共享一个创作条目身份和父级关系，但保留各自类型数据。文件夹可以包含文件夹与画布，画布是叶子条目。

## 3. 产品模型与术语

### 3.1 Creative Entry（创作条目）

工作台中可被命名、收纳、排序、移动和管理的统一条目抽象。首期有两种类型：`FOLDER` 与 `CANVAS`。创作条目不是项目，不隐含项目类型、项目状态、成员或项目生命周期。

### 3.2 文件夹

一种创作条目，用于组织子文件夹和画布。文件夹可无限嵌套；每个文件夹只有一个直接父文件夹，或位于根目录。

### 3.3 画布

一种创作条目，包含可编辑的画布内容。画布只能有一个直接父文件夹，或位于根目录；画布不能成为其他条目的父级。

### 3.4 根目录与最近打开

- 根目录是系统提供的虚拟容器，不是可编辑条目；`parent_entry_id = NULL` 表示根目录。
- “最近打开”是快捷视图，不改变条目归属。最近打开记录按用户与画布维护。
- 首期不强制增加“未归档”实体；根目录直接呈现根级文件夹和画布。

### 3.5 缩略图语义

- 创作条目可保存可选的用户自定义封面引用，作为工作台通用展示信息。
- 画布自动生成的预览缩略图属于画布专属数据，保存在画布类型数据中。
- 文件夹的自动预览（例如由子画布拼成的封面）默认按需聚合，不作为条目自定义封面写入。
- 缩略图字段存稳定的媒体/对象引用 ID，不存二进制内容或短时签名 URL。媒体服务/对象存储的正式契约待定。

## 4. 目标与成功指标

### 4.1 目标

1. 用户能在一个工作台目录中查看并混合排列文件夹与画布。
2. 用户能按自己的语义创建嵌套目录，而不必建立额外项目对象。
3. 用户能快速打开、重命名、移动、排序、搜索和恢复条目。
4. 画布内容与目录组织解耦，目录变更不改动画布身份或内容。

### 4.2 指标

- 工作台首屏目录加载成功率 ≥ 99.5%。
- 创建、重命名和移动等目录操作成功率 ≥ 99%。
- 上线前采集“进入工作台后 30 秒内打开画布”基线，再设定提升目标。
- 误删除导致内容不可恢复事件为 0。

## 5. 用户与用户故事

目标用户为需要管理多张画布的个人创作者。团队协作不在首期范围。

### US-001：建立自己的目录结构

作为创作者，我想创建并嵌套文件夹，以便按作品、客户或创作阶段组织画布。

验收：

- [ ] 可在根目录或当前文件夹创建文件夹。
- [ ] 至少三级嵌套后，刷新仍能还原层级。
- [ ] 文件夹可重命名；名称去除首尾空格后不能为空。
- [ ] 无效字符或超过产品长度限制的名称被拒绝并给出可理解提示。

### US-002：管理混排条目

作为创作者，我想在同一目录中看到文件夹和画布，并调整其顺序，以便按自己的优先级排列。

验收：

- [ ] 当前目录列表同时显示直属文件夹和直属画布。
- [ ] 两类条目共享同一排序顺序，可以交错排列。
- [ ] 刷新后顺序保持；并发重排冲突时提示刷新。

### US-003：创建并打开画布

作为创作者，我想从当前目录创建画布，并从列表打开画布继续编辑。

验收：

- [ ] 新画布默认成为当前目录的子条目。
- [ ] 从根目录创建的画布显示在根目录。
- [ ] 打开画布不改变其父级和排序位置。
- [ ] 画布自动预览与用户自定义封面来源清晰，不互相覆盖。

### US-004：移动条目

作为创作者，我想将画布或文件夹移动到其他目录，以便调整组织方式。

验收：

- [ ] 可通过拖放或“移动到…”目录选择器移动条目。
- [ ] 可用键盘完成同样的移动操作。
- [ ] 不能把文件夹移动到自身或自身后代。
- [ ] 不能移动画布到其下级（画布没有子目录能力）。
- [ ] 移动不改变条目 ID、画布内容或缩略图身份。

### US-005：查找和继续工作

作为创作者，我想搜索条目并查看最近打开的画布，以便快速找回内容。

验收：

- [ ] 搜索文件夹和画布名称；结果展示条目类型及完整目录路径。
- [ ] 最近打开按最近打开时间倒序，重复打开只更新同一条记录。
- [ ] 已删除或无权访问的画布不出现在最近打开结果中。

### US-006：安全删除与恢复

作为创作者，我想删除条目并在误操作后恢复，以免意外丢失内容。

验收：

- [ ] 删除画布和文件夹有明确反馈；非空文件夹删除前说明处理策略及影响数量。
- [ ] 删除为软删除；保留期内可从回收站恢复。
- [ ] 恢复时原父级已删除则放回根目录，且不会恢复到无效父级。
- [ ] 递归删除若提供，必须明确列出影响范围并二次确认。

## 6. 功能需求

### 6.1 目录浏览与列表

- FR-1：工作台按需加载根目录或指定文件夹的直属条目，不默认一次性加载整棵树。
- FR-2：列表项统一返回条目 ID、类型、名称、父条目 ID、顺序、时间和展示缩略图信息。
- FR-3：列表返回文件夹路径/面包屑；搜索结果必须含完整路径。
- FR-4：文件夹与画布可以自由混排，由统一 `sort_order` 决定顺序。
- FR-5：支持网格/列表视图、名称/最近修改/创建时间排序；手动排序为显式模式。

### 6.2 创建、命名与移动

- FR-6：创建文件夹或画布时，调用方指定目标父级；服务端验证目标是当前用户可访问的有效文件夹。
- FR-7：名称限制在产品层设定；建议上限 100 个 Unicode 字符，拒绝控制字符及空白名称。
- FR-8：同级条目允许同名，首期不以名称作为身份或唯一键。
- FR-9：移动通过条目 ID 和目标父级 ID 执行；`NULL` 目标代表根目录。
- FR-10：拖放为快捷交互，“移动到…”必须作为可发现且键盘可操作的等价方式。
- FR-11：批量移动不在 MVP；接口设计避免阻碍后续增加批量命令。

### 6.3 排序

- FR-12：同一父级下的文件夹和画布共享排序域，数据库在统一创作条目记录上存 `sort_order`。
- FR-13：手动排序以用户操作为准；首次进入目录可使用创建时间倒序的默认次序初始化，之后不自动重排。
- FR-14：排序值相同时以 `created_at`、`id` 作为稳定兜底，不以不同子表的独立主键排序来表达用户顺序。
- FR-15：移动到新父级时，在目标目录末尾分配顺序；同一父级内重排不得产生重复或不可稳定的顺序。

### 6.4 删除、回收与恢复

- FR-16：删除标记作用于条目；父文件夹软删除时，其后代从常规目录、搜索和最近打开中隐藏。
- FR-17：非空文件夹删除策略需提供两种可讨论选项：将直属子项提升到其父目录/根目录，或递归删除整个子树。产品默认策略待确认。
- FR-18：递归软删除应在一个事务/一致性工作流中完成；若规模导致单事务不可行，采用可恢复的异步任务并展示处理中状态。
- FR-19：建议回收站保留 30 天；保留期到期后由清理任务永久删除关联数据/对象，具体级联保留策略待定。
- FR-20：恢复父文件夹时按策略恢复后代；恢复画布时若原父级无效则放回根目录。

### 6.5 搜索与快捷视图

- FR-21：首期按名称搜索文件夹和画布；在“当前文件夹”搜索限定后代范围，在“全部内容”搜索整个用户空间。
- FR-22：支持最近打开画布视图，默认分页展示 20 条。
- FR-23：状态筛选（例如草稿、生成中、待确认）由画布领域提供；Creative Entry 不复制画布状态。
- FR-24：不在首期引入收藏、标签、全文检索或跨用户共享。

### 6.6 缩略图

- FR-25：条目保存可选的用户自定义封面引用。
- FR-26：画布自动预览归画布专属数据；若存在自定义封面，展示优先级需明确（建议自定义封面优先，自动预览作为回退）。
- FR-27：文件夹可显示自定义封面，或由直属子画布自动生成聚合预览；聚合预览不写入自定义封面字段。
- FR-28：工作台摘要 API 返回适合列表展示的缩略图引用/可访问 URL；短时签名 URL 不作持久化事实数据。

## 7. 技术方案

### 7.1 逻辑数据模型

使用统一的 `creative_entry` 表表达共有身份、树关系和混排顺序；文件夹/画布专属字段保留在类型表。该抽象命名来自创作内容领域，不与画布内部的节点（node）概念冲突。

```text
creative_entry
- id                 全局唯一创作条目 ID
- owner_id           用户主体 ID
- parent_entry_id    可空；根目录为 NULL
- entry_type         FOLDER / CANVAS
- name               展示名称
- sort_order         同一父级内的统一排序值
- custom_cover_id    可空；稳定媒体引用
- created_at
- updated_at
- deleted_at         可空，软删除
- version            并发版本

creative_folder
- entry_id           PK，同时 FK -> creative_entry.id
- folder-specific fields (首期可为空，暂不为抽象而造字段)

canvas
- entry_id           PK，同时 FK -> creative_entry.id
- canvas-specific fields (画布内容、状态、自动预览引用等)
```

如果现有画布数据已持久化，`canvas.entry_id` 表示关系模型；实际迁移应根据当前画布主键与内容表拆分方式决定是否直接把 `creative_entry.id` 作为画布 ID，避免无必要地引入双 ID。Creative Entry 与画布身份的映射必须稳定。

### 7.2 数据库约束与风险

- `creative_entry.id` 主键全局唯一；`owner_id` 来自可信认证上下文，不能由客户端指定。
- 增加 `(id, owner_id)` 唯一键；`(parent_entry_id, owner_id)` 复合外键引用 `(id, owner_id)`，防止跨用户挂接父条目。
- `parent_entry_id` 为空表示根目录，不创建可删除的根条目记录。
- `entry_type` 使用受约束的封闭值；迁移应按仓库规则使用 Flyway。
- 活跃条目目录索引建议为 `(owner_id, parent_entry_id, sort_order, id) WHERE deleted_at IS NULL`；搜索索引按实际 PostgreSQL 搜索方案评估。
- 普通关系外键无法保证父条目的 `entry_type = FOLDER`、画布没有子级，以及类型条目与扩展表一一匹配。领域层负责校验；数据库可用触发器/延迟约束强化，但首期是否引入触发器需评审，避免规则散落在难以测试的数据库逻辑中。
- 文件夹移动需检测目标是否位于源文件夹后代中，避免环。关系型邻接表可通过递归查询检测；若后续规模/查询压力证明必要，再评估闭包表或物化路径，不为首期预优化。
- 并发拖动/重排使用 `version` 乐观锁；冲突返回可识别的业务错误，客户端刷新重试。

### 7.3 查询和排序实现

- 目录列表通过 `parent_entry_id` 查询一页直属 `creative_entry`，天然得到文件夹与画布的统一顺序。
- 对画布条目批量读取画布摘要/状态/自动预览；对文件夹条目读取文件夹摘要或计算其子项预览，避免逐条 N+1 查询。
- 单页返回的条目按 `sort_order ASC, created_at ASC, id ASC` 稳定排序。
- 最近打开使用独立记录：`user_id, canvas_entry_id, last_opened_at`，以 `(user_id, canvas_entry_id)` 唯一；每次打开原子更新时间。若用户空间永远严格为个人所有，可评审是否简化为画布字段，但独立记录更能表达用户行为且支持未来多成员。
- 树导航按层加载；完整祖先路径可通过递归查询获取，并设置安全的最大响应深度，产品逻辑仍不人为限制目录层级。

### 7.4 API 草案

所有端点在 `/api/v1/creative-entries` 下，具体服务路由待模块边界确认。

- `GET /creative-entries?parentId={id|null}&cursor=...`：取直属条目分页。
- `GET /creative-entries/tree?parentId=...`：按层获取文件夹树节点摘要。
- `GET /creative-entries/search?q=...&scope=...`：名称搜索，结果附路径。
- `POST /creative-entries/folders`：创建文件夹，传 `parentId`、`name`。
- `POST /creative-entries/canvases`：创建画布并指定父级；是否由同一服务创建画布待定。
- `PATCH /creative-entries/{id}`：改名、设置自定义封面等允许的通用条目属性。
- `POST /creative-entries/{id}/move`：移动到目标父级并携带版本。
- `POST /creative-entries/{id}/reorder`：提交同级排序变更及版本。
- `DELETE /creative-entries/{id}`：按明确策略软删除。
- `POST /creative-entries/{id}/restore`：恢复条目。
- `GET /creative-entries/recently-opened`：查询最近打开画布。

写接口从会话获得用户主体 ID；目标父级所有权和条目类型都由服务端校验。响应使用应用 DTO，不返回 Entity 或领域聚合。

### 7.5 后端分层建议

- 限界上下文：创作内容/画布上下文中的工作台目录能力；身份上下文仅提供稳定的用户主体 ID。
- 聚合候选：`CreativeEntry` 聚合维护条目类型、名称、父级和可变更规则；移动文件夹时用领域服务或应用层查询协调后代环检测。若画布内容本身是独立高并发大聚合，画布内容不纳入该聚合事务。
- Application 用例：创建文件夹、创建画布入口协调、重命名、移动、重排、软删除、恢复、分页浏览、搜索、记录最近打开。
- Repository 端口位于 domain 或 application 的合理边界；MyBatis-Plus Mapper/Entity/Wrapper 只在 infrastructure；持久化转换使用 MapStruct `Converter`。
- 目录关系变更只更新条目元数据，不重写画布内容；媒体/对象存储删除等外部副作用在事务提交后通过可靠机制处理。
- 若画布未来由独立服务拥有，Creative Entry 只存稳定画布 ID 和目录元数据，需用跨上下文契约协调创建/删除，不共享画布 Entity。

### 7.6 删除与一致性策略

- 同父级直属列表、移动、改名和排序在单个数据库事务中完成。
- 软删除整棵子树需要原子可见性。首期可用单事务批量更新；若树很大导致事务过重，切换到删除任务状态和分批执行，但要保证处理中子树不会部分暴露。
- 对象存储清理、媒体缩略图清理不与数据库事务同步远程调用；记录待处理副作用，在提交后可靠执行并允许重试。
- 恢复检查父级有效性；父级不存在/已删除时将条目放回根目录并返回实际恢复位置。

### 7.7 测试方案

- 领域测试：名称规则、条目类型规则、画布不可作父级、文件夹环检测、删除/恢复规则。
- 应用测试：所有权校验、事务协调、移动/排序冲突、删除策略、最近打开幂等更新。
- Adapter 集成测试：PostgreSQL 外键/索引/分页/乐观锁、递归父级查询、软删除过滤、MapStruct 映射。
- 接口测试：越权访问、错误码、参数校验、父级类型错误、搜索路径与分页响应。
- ArchUnit：domain 不依赖框架/基础设施，interfaces 不接触 Mapper，application 不依赖 Adapter。

## 8. 非目标

- 不保留或引入 Project/项目业务实体。
- 不做团队工作区、共享权限、协作评论和跨用户转移。
- 不做文件夹快捷方式或同一画布多处归档。
- 不做全文搜索、智能归档、标签、收藏和批量操作。
- 不将图片二进制或短时访问 URL 存入创作条目表。
- 不为未来假设的任意内容类型建立复杂插件体系；扩展新类型前需确认其是否适合成为 Creative Entry。

## 9. 非功能需求

- 目录分页接口服务端 P95 < 500ms（不含网络，目标数据规模待压测定义）。
- 首屏只加载直属条目摘要；批量加载类型摘要，避免 N+1。
- 用户 A 无法读取、移动、重命名、删除或恢复用户 B 的条目。
- API 版本为 `/api/v1`，时间以 UTC 存储。
- 对创建/移动/删除/恢复记录不含内容正文的审计事件。
- 目录变更失败时维持事务前状态；并发冲突可被客户端识别并恢复。

## 10. 验收标准

- 用户可建立多级文件夹，文件夹与画布能在同目录中混排并持久化顺序。
- 任一目录列表都稳定分页，排序平局时刷新不会随机跳动。
- 新建、移动画布后其条目 ID 与画布内容 ID 映射保持稳定。
- 系统拒绝跨用户父级、画布作为父级和文件夹循环移动。
- 文件夹自定义封面、画布自定义封面和自动预览来源按明确优先级展示。
- 软删除、回收站、恢复和过期清理遵循已确认策略；不会因删文件夹误删画布内容。
- 搜索结果能显示完整路径；最近打开按时间排序且无重复条目。
- 自动化领域、应用、Adapter、接口与架构测试覆盖关键规则。

## 11. 待讨论事项

1. Creative Entry 是否作为正式领域术语，以及中文统一译名是否定为“创作条目”。
2. 文件夹删除默认采取“子项提升到父级/根目录”还是“递归软删除”。
3. 是否首期提供回收站；若提供，建议保留 30 天。
4. 手动排序与名称/最近修改排序如何切换；建议选择手动排序时将其持久化为用户目录顺序。
5. 自定义封面是否允许所有条目设置；画布自定义封面与自动预览的展示优先级建议自定义封面优先。
6. 首期文件夹自动预览采用前端拼图、服务端返回子画布摘要，还是暂不提供。
7. 最近打开是仅个人记录还是未来按成员区分；建议采用独立用户行为表。
8. 媒体服务当前是否已有稳定的资源引用 ID/API；若没有，应先定义缩略图读取与鉴权契约。
9. 同一父目录内是否允许同名条目；本稿建议允许，避免命名唯一性阻塞整理。
