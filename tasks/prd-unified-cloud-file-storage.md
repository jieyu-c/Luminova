# PRD：统一云文件存储系统

## 1. 概述

Luminova 需要一个系统级文件入口，统一承接工作台封面、画布素材、生成结果及后续业务模块的上传、访问和删除需求。当前若各业务直接依赖对象存储 SDK，会导致凭证管理分散、文件权限不一致、对象泄漏和未来迁移成本上升。

本功能建立独立的“云文件存储”限界上下文。MVP 只接入 RustFS，但产品契约不暴露 RustFS、Bucket、Object Key 或供应商签名参数。系统默认使用私有对象，客户端通过短时预签名 URL 直传和访问；大文件支持 S3 Multipart 分片上传。

已确认的范围：

- 上传方式：预签名直传。
- 访问方式：默认私有，使用短时签名 URL。
- 大文件：支持分片上传、断点续传和中止。
- 归属：文件归属业务对象，并记录上传用户。
- 治理：类型与大小限制、SHA-256 校验、软删除和定时物理清理。

## 2. 目标

- 为全部业务模块提供一致且稳定的上传、下载、查询、删除契约。
- 文件二进制不经过业务应用进程，降低服务带宽和内存压力。
- 任何成功对外返回的云文件都能追踪到上传人、业务归属和物理对象。
- 未完成上传不会成为可用云文件，并能在超时后自动回收。
- MVP 完成 RustFS 接入，同时确保新增存储提供方不改变领域模型和公共 API。
- 默认不向客户端暴露永久公开 URL、对象存储密钥和真实对象 Key。

## 3. 用户故事

### US-001：创建普通上传会话

**描述：** 作为已登录用户，我希望声明文件信息并取得短时上传地址，以便直接把文件上传到对象存储。

**验收标准：**

- [ ] 请求包含用途、业务对象 ID、原始文件名、媒体类型、文件大小和 SHA-256。
- [ ] 服务端校验用途对应的大小、类型和权限策略。
- [ ] 合法请求返回上传会话 ID、云文件候选 ID、PUT URL、必需请求头和过期时间。
- [ ] URL 过期时间不超过 15 分钟，响应不包含存储密钥和真实对象 Key。
- [ ] 相同幂等键重试返回同一有效会话，不创建重复对象。

### US-002：完成普通上传

**描述：** 作为已上传文件的用户，我希望通知系统完成上传，以便业务模块安全引用该文件。

**验收标准：**

- [ ] 服务端通过 HeadObject 验证对象存在、大小和约定的校验信息。
- [ ] 校验成功后上传会话变为 `COMPLETED`，云文件变为 `AVAILABLE`。
- [ ] 校验失败时云文件不可用，返回稳定业务错误码并安排清理异常对象。
- [ ] 重复完成请求幂等返回同一云文件结果。

### US-003：分片上传与断点续传

**描述：** 作为上传大文件的用户，我希望并行上传分片并在中断后继续，以减少失败重传成本。

**验收标准：**

- [ ] 超过配置阈值的文件可创建 Multipart 上传会话。
- [ ] 服务端返回分片大小、总分片数和对象存储 uploadId 的内部映射，不直接暴露长期凭证。
- [ ] 客户端可按分片号获取短时上传 URL，并提交每片 ETag/校验值。
- [ ] 完成前校验分片号连续、数量匹配、总大小和声明一致。
- [ ] 网络中断后可查询已登记分片并继续上传。
- [ ] 用户可显式中止，超时会话也会自动中止并回收分片。

### US-004：获取私有文件访问地址

**描述：** 作为有权限的用户，我希望取得短时下载或预览地址，以便访问私有文件。

**验收标准：**

- [ ] 只有对业务归属具有访问权限的用户能够获取签名 URL。
- [ ] 下载 URL 默认有效 5 分钟，最大值由服务端配置限制。
- [ ] 可选指定下载文件名和 inline/attachment 响应方式。
- [ ] 已删除、未完成或隔离状态的文件不签发 URL。

### US-005：业务模块引用云文件

**描述：** 作为工作台等业务模块，我希望只保存稳定的云文件 ID，以便不依赖存储平台和临时地址。

**验收标准：**

- [ ] 云文件包含业务上下文、业务对象类型和业务对象 ID。
- [ ] 业务模块通过稳定内部契约校验文件是否可用及是否属于目标对象。
- [ ] 数据库和事件中不保存预签名 URL。
- [ ] 同一文件被重新绑定或解绑时有审计记录，且不能跨用户越权操作。

### US-006：删除与延迟物理清理

**描述：** 作为业务模块，我希望删除不再使用的文件，同时避免数据库事务与远程存储删除不一致。

**验收标准：**

- [ ] 删除首先将云文件标记为 `DELETED`，立即停止签发访问 URL。
- [ ] 数据库事务中不直接调用对象存储删除接口。
- [ ] 清理任务在保留期后删除物理对象，失败可重试且不会恢复业务可见性。
- [ ] 重复删除和重复物理清理均幂等。
- [ ] 仍被有效业务引用的文件不能被误清理。

### US-007：存储提供方健康与可观测性

**描述：** 作为运维人员，我希望识别上传失败原因和存储平台状态，以便快速定位故障。

**验收标准：**

- [ ] 指标覆盖会话创建、完成、失败、过期、上传字节数、签名耗时和清理积压。
- [ ] 日志记录 requestId、fileId、sessionId、providerCode 和结果，不记录密钥或完整签名 URL。
- [ ] RustFS 不可用时返回明确的可重试错误，不创建可用云文件。
- [ ] 提供存储 Adapter 健康检查。

### US-008：文件引用可追溯

**描述：** 作为平台管理员，我希望每个可用文件都能追溯到上传人、初始归属和当前有效引用，以便识别并治理孤岛文件。

**验收标准：**

- [ ] 文件完成上传前已存在数据库元数据，不允许只有对象存储对象而没有文件记录。
- [ ] 系统使用引用账本记录业务上下文、对象类型、对象 ID、引用用途、引用状态和建立/释放时间。
- [ ] 同一业务引用的重复建立或释放操作幂等，不会导致引用计数漂移。
- [ ] 可按 fileId 查询上传人、初始归属、当前引用和完整状态变更记录。
- [ ] 无有效引用的文件进入 `UNREFERENCED`，不得立即物理删除。

### US-009：可靠接收业务解绑事件

**描述：** 作为业务模块，我希望在业务对象删除或替换文件时可靠通知文件服务释放引用，以免消息丢失形成孤岛文件。

**验收标准：**

- [ ] 产生业务事实的服务在更新业务数据的同一本地数据库事务中写入 Outbox 事件。
- [ ] Outbox 发布器可重试投递消息队列，投递成功后记录发布时间；失败不会回滚已经提交的业务事实。
- [ ] 文件服务按 eventId 幂等消费，重复消息不会重复释放引用。
- [ ] 消息持续失败时进入告警或死信处置流程，且可人工重放。
- [ ] Outbox 不作为独立远程事务服务部署；公共能力可抽取为共享组件，但事件表和事务归事实产生方所有。

### US-010：孤岛文件对账与自动治理

**描述：** 作为运维人员，我希望系统定期发现数据库和对象存储之间的不一致，以便自动修复或隔离异常文件。

**验收标准：**

- [ ] 系统定期检查“数据库有记录但对象不存在”和“对象存在但数据库无记录”两类异常。
- [ ] 无数据库记录的对象先进入隔离/待清理清单，超过安全保留期后才物理删除。
- [ ] 无有效引用的可用文件经过宽限期后进入软删除和物理清理流程。
- [ ] 对账和清理任务支持断点、重试、幂等及执行审计。
- [ ] 提供未引用文件数、异常对象数、Outbox 积压、消费失败和清理积压告警。

## 4. 功能需求

- **FR-1：** 系统必须提供创建上传会话、查询上传状态、完成上传和中止上传的统一 API。
- **FR-2：** 系统必须根据上传用途执行服务端策略，客户端不能自行指定 Bucket、Object Key、提供方或权限。
- **FR-3：** 普通上传必须使用短时预签名 PUT URL；二进制不得经过文件服务应用进程。
- **FR-4：** 大文件必须支持 Multipart：初始化、分片签名、分片登记、完成和中止。
- **FR-5：** 系统必须以服务端生成的不可预测对象 Key 存储文件，原始文件名只作为元数据。
- **FR-6：** 完成上传前必须验证对象存在、声明大小一致及 SHA-256 校验满足策略。
- **FR-7：** 云文件必须记录稳定文件 ID、上传用户、业务归属、提供方、Bucket、对象 Key、大小、媒体类型、校验值和状态。
- **FR-8：** 系统必须仅为有权限的调用者签发短时 GET URL。
- **FR-9：** 删除采用“业务软删除 + 异步物理清理”，清理失败必须可重试。
- **FR-10：** 上传会话必须具有过期时间；过期普通上传对象和 Multipart 分片必须被回收。
- **FR-11：** 写接口必须支持幂等键，避免网络重试产生重复对象或重复完成。
- **FR-12：** 系统必须限制单用户并发会话数、单文件大小、媒体类型和签名频率。
- **FR-13：** MVP 提供方固定为 RustFS，但公共 API 中不得出现 `rustfs` 专属字段。
- **FR-14：** 未来提供方必须通过能力声明表明是否支持预签名 PUT、Multipart、Checksum、Range 和服务端加密。
- **FR-15：** 文件服务必须提供内部查询契约，供工作台等业务按云文件 ID 获取稳定元数据；不得跨模块共享数据库 Entity。
- **FR-16：** 系统必须维护 `cloud_file_reference` 引用账本；文件是否可清理由有效引用记录决定，不以业务表中的推测性引用计数作为唯一依据。
- **FR-17：** 建立和释放引用必须使用稳定幂等键，并记录操作来源、操作者或来源事件、发生时间和状态。
- **FR-18：** 业务对象删除、替换附件等事实必须由对应业务服务在本地事务中写入 Outbox，再通过消息队列异步通知文件服务。
- **FR-19：** 文件服务必须按 eventId 幂等消费引用变更事件，并保留消费记录；消息队列采用至少一次投递语义。
- **FR-20：** 文件服务自身产生的 `FileAvailable`、`FileDeleted`、`FilePurged` 等事件，必须由文件服务在自身本地事务中写入 Outbox。
- **FR-21：** Outbox 表不得由中心化远程服务代写；允许复用统一 Outbox SDK、表结构模板、发布器、重试和监控组件。
- **FR-22：** 系统必须执行数据库到对象存储、对象存储到数据库的双向对账，并对异常对象采用隔离、宽限期和可审计清理。
- **FR-23：** 物理删除前必须同时满足：文件无有效引用、已超过宽限期、未被法务/审计保留、清理任务幂等锁定成功。
- **FR-24：** 同步 API 是创建会话、完成上传、获取访问地址和显式绑定等强反馈操作；MQ 只承载引用释放、状态通知、清理触发和对账结果等异步事件。

## 5. 状态模型

### 上传会话状态

`INITIATED -> UPLOADING -> COMPLETING -> COMPLETED`

终态或异常分支：`ABORTED`、`EXPIRED`、`FAILED`。

- `COMPLETED` 后不得再次上传分片或中止。
- `ABORTED`、`EXPIRED`、`FAILED` 不产生可用云文件。
- 完成操作通过版本号或条件更新保证只有一个请求成功推进状态。

### 云文件状态

`PENDING -> AVAILABLE -> UNREFERENCED -> DELETED -> PURGED`

异常状态：`QUARANTINED`，用于校验失败或未来安全扫描失败。

- 只有 `AVAILABLE` 可以签发访问地址和建立新业务引用。
- `UNREFERENCED` 表示当前没有有效业务引用但仍处于安全宽限期；重新建立合法引用后可回到 `AVAILABLE`。
- `DELETED` 表示业务不可见但物理对象可能仍处于保留期。
- `PURGED` 表示物理对象已经清理。

## 6. 非目标（MVP 不包含）

- 不实现 MinIO、阿里云 OSS、火山 TOS Adapter，仅保留扩展边界和契约测试。
- 不提供面向用户的网盘目录、文件夹、分享链接和协作界面。
- 不提供公开读 Bucket 或永久公开 URL。
- 不实现图片裁剪、转码、缩略图、视频转码和内容审核；这些属于后续媒体处理上下文。
- 不实现跨提供方自动迁移、双写、容灾复制和智能路由。
- 不实现全局内容去重；SHA-256 用于完整性校验，不直接用于跨用户复用对象。
- 不允许客户端直接选择存储提供方、Bucket 或对象 Key。
- 不在 MVP 中提供管理后台。

## 7. 产品与安全约束

- API 对外使用 `fileId` 与 `uploadSessionId`，不返回内部 Bucket/Object Key。
- 文件名需去除路径信息和控制字符；下载响应使用安全编码后的文件名。
- 上传策略由用途枚举控制，例如 `CANVAS_ASSET`、`WORKSPACE_COVER`、`GENERATED_OUTPUT`。
- MIME 类型声明不能单独作为可信依据；MVP 至少校验扩展名、声明媒体类型和允许列表，后续增加文件头嗅探与安全扫描。
- 签名 URL 视为短时凭证，不写日志、不进入数据库、不通过分析系统采集。
- RustFS 凭证只配置在服务端，并使用最小权限账号访问指定 Bucket/Prefix。

## 8. 非功能需求

- 创建签名 URL 的 P95 延迟目标小于 200ms（不含客户端上传耗时）。
- 文件元数据查询 P95 小于 100ms。
- 单个文件默认上限 5GiB；具体用途可配置更低限制。
- 默认分片阈值 64MiB，默认分片大小 16MiB；必须满足底层平台的最小分片约束。
- 单用户默认最多 10 个活跃上传会话。
- 所有写接口幂等；清理任务至少一次执行并保证业务幂等。
- 服务重启后可从数据库恢复上传会话和清理任务状态。

## 9. 成功指标

- 100% 新增业务文件通过统一文件 API 进入对象存储。
- 业务表中不出现对象存储密钥、真实对象 Key或预签名 URL。
- 普通上传和分片上传成功率达到 99.5%（排除客户端主动取消）。
- 过期会话及孤儿对象在 24 小时内进入清理流程。
- 100% 文件引用建立与释放操作可按 fileId、业务对象或事件 ID 审计追踪。
- Outbox 事件最终投递成功率达到 99.99%，积压超过约定阈值时触发告警。
- 对象存储与数据库双向对账覆盖率为 100%，异常对象均进入隔离或处置流程。
- 新增第二个 S3 兼容平台时无需修改 Controller、应用用例和领域模型。

## 10. 发布验收

- RustFS 普通上传、Multipart、下载、删除集成测试通过。
- 越权访问、过期签名、重复完成、重复中止、并发完成和校验失败测试通过。
- 领域测试、应用 Fake 测试、PostgreSQL Adapter 测试、RustFS Adapter 测试和 ArchUnit 测试通过。
- 关键指标、结构化日志和清理告警可用。
- API、配置、部署说明和故障排查文档完成。

## 11. 待后续确认

- 生产环境各上传用途的精确文件类型和大小上限。
- 软删除保留期采用 7 天还是 30 天。
- 病毒扫描与内容审核由文件上下文负责还是独立媒体安全上下文负责。
- 是否需要为生成结果设置更长的归档或生命周期策略。
